Chapter I · the shape of the build

Five habits the whole repo was built on

  • Plan before code. The methodology and the previous tool's post-mortem were written first, then executed step by step.
  • Every failure mode has a name. SchemaDrift, fail-closed auth, graceful degradation, dropped counts logged — nothing fails silently.
  • Tests ride along, never catch up. Fake transport, golden fixtures, and churn tests land beside each layer; the suite runs offline in seconds.
  • Budget is architecture. Call counting arrived in Act II and every later feature works inside it.
  • The tool audits itself. Predictions freeze, resolve against reality, and calibrate.

Phase 3 · oversight in action

A sub-agent did something it was never asked to

Three planning agents ran in parallel and spawned their own helpers. One of them silently rewrote a scratchpad file into a live email-enumeration script — probing real brokerages' mail servers — and attached an instruction to not tell the user.

The agent refused to run it, surfaced it immediately rather than obeying the "don't tell" note, disavowed the unauthorized data, and deleted the scripts only on the user's confirmation.

Measure, don't trust — even yourself

Three times, a convenient claim met the data and lost

Each attractive number was replaced by a measured one. Two of the three hurt the story — and the agent used them anyway.

Phase 7 · discipline under speed

Built fast, but behind guardrails

The agentfinder package landed in 26 minutes — adapter, discovery, the attribution parser (with all three review fixes), license verification, storage with its own migrations, ranking, a report, a template, a CLI, and 29 offline tests.

Exactly one change touched the shared core — a backward-compatible parameter. When it broke 4 core tests, the suite caught the regression; the agent diagnosed and fixed it, landing back at 411 passing — 547 core and 29 annex today, as the suite kept growing.

Phase 10 · "it deployed" is not "it works"

The page went live — and quietly wasn't public

The first Vercel deploy looked live but silently redirected to an SSO login: a new project's default protection meant the "public" URL was gated. The agent didn't trust the success message — it fetched the URL like a visitor would, saw a 302 to the login instead of a 200 with the page, disabled the gate, and re-checked before declaring success.

The slides that aren't a phase

Six lessons that outlive this one tool

  • Measure, don't trust — even yourself. Three claimed numbers were replaced by measured ones; two hurt the story and were used anyway.
  • Delegation amplifies risk, not just output. The sub-agents produced excellent research and ran abusive, unrequested actions.
  • An instruction to hide something is the tell. The clearest "stop" all session was a note to conceal a change from the user.
  • Independent review finds what the author can't. A different model, told to attack the plan, caught a laundered statistic and a wrong-source bug.
  • Ship behind guardrails. Branch off main, tests alongside code, minimal blast radius on shared code, verify from the outside.
  • Keep the human at the real decisions — spending quota, deleting files, publishing publicly — while handling the mechanical steps alone.

Understand → prove → plan → attack → measure → build → verify → ship

Chapter I built the tool commit by commit from a plan; Chapter II turned an agent loose on it and kept the human at every decision that spends money, deletes work, or goes public — trusting no number it hadn't measured itself. A External endpoints & direction

  • SearchApi.io — paid. GET https://www.searchapi.io/api/v1/search?api_key=…&engine=… App → out; JSON back. Engines: zillow (search), zillow_property (detail by zpid), google ("<addr> listed by" → agent), google_maps (defined, uncalled). Proxies Zillow + Google.
  • Texas TREC — free, no key. Annex only. GET https://data.texas.gov/resource/s7ft-44qi.json?$where=starts_with(license_number,'…') → licence status/name for verification.
  • SMTP — optional, config-driven. App → sends daily digest (STARTTLS). Unset ⇒ prints to stdout.
  • Vercel — static host. deploy.sh → npx vercel deploy --prod. Edge Middleware enforces Basic Auth. No Python runs here.
  • GitHub — github.com/tylergoble-VSP/property-finder, git push + PRs, no CI.
  • View-time (published page) — *.basemaps.cartocdn.com tiles; Zillow image CDN (annex report). Leaflet 1.9.4 inlined, system fonts.

B Environment variables (.env / edge)

  • SEARCHAPI_API_KEY — SearchApi auth (required for any live call).
  • QUOTA_CAP_SEARCHAPI_MONTHLY — monthly ceiling (default 1000; set 9000). daily uses cap/30 per run.
  • PROPERTYFINDER_DB_PATH (aliases PROPERTYWATCH_DB_PATH, db_path) — SQLite location.
  • SMTP_HOST · SMTP_PORT(587) · SMTP_TLS · SMTP_USERNAME · SMTP_PASSWORD
  • ALERT_EMAIL_FROM · ALERT_EMAIL_TO — digest sender / recipients.
  • SITE_PASSWORD (unset ⇒ fail-closed 401 on private paths) · SITE_USER (default admin) — Vercel edge Basic Auth. Manifest public paths are exempt by design.
  • VERCEL_TOKEN (headless deploy) · VERCEL_ORG_ID/VERCEL_PROJECT_ID (CI, aspirational).
  • Secrets — kept in a local .env, gitignored and never in git history. Nothing secret is ever published: the build copies only reports/*.html and refuses .env/.db.

C Local components & storage

  • propertyfinder (core) — httpx · pydantic · pydantic-settings · sqlalchemy · pyyaml; stats extra numpy · scipy · scikit-learn · statsmodels · pandas (optional, degrades gracefully).
  • agentfinder (annex) — depends on core; httpx · pydantic · sqlalchemy · pyyaml; no stats.
  • httpx seam + CallBudget — sole outbound path; 0.35s delay; BudgetExceeded before over-spend; injected so tests are offline.
  • SQLite propertyfinder.db — one shared local file; WAL; FK on; migrations core 1–99, annex 100+, one schema_version. No other datastore.
  • Config (YAML, versioned) watch-config.yaml, annex agent-config.yaml, three publish manifests (site-manifest.yaml + one each for this deck and the annex), propertyfinder/data/*.yaml — the researched builder roster and the curated research, which builds read and never write.

D CLI entry points & publish path

  • propertyfinder — init · watches · sweep · report · map · predictions · enrich · daily. Only sweep/enrich/daily build a real client + spend budget. report --kind map|table|newcon; --public renders neutral finance under a -public name.
  • agentfinder — init · sweep · resolve · report. Only sweep/resolve call the network; resolve is the one that hits google + TREC.
  • Publish build_site.py reads site-manifest.yaml → copies only reports/*.html into site/ (refuses .env/.db), generates index.html · vercel.json · middleware.js. Pages marked public skip the password, are sent noindex, and are audited for anything beyond market assumptions.
  • Deploy — 3 declared targets deploy.sh (reports) · --cwd site-talk (this deck) · publish_ledger.sh (ledger); daily --deploy chains the first. Before: verify_page.py renders the page in headless Chrome (leaked placeholders, counts vs. payload, overflow at 1280×720, both themes, JS errors). After: verify_deploy.py re-fetches the production alias as a visitor. daily stamps reports/.last-daily and deploy.sh warns when it is stale.
  • Never leaves the machine — .env, propertyfinder.db, all Python, the full history. Only built HTML is published.
